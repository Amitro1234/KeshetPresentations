# Session Insight: Migrating and Standardizing Legacy Bundled Presentations

**Date:** 2026-08-05
**Author:** Senior Presentation Systems Engineer

---

## Task / Problem Summary
The goal was to migrate `vibe-coding-guide.html` onto the newly established presentation design system. The legacy deck was in a bundled format (JSON-serialized HTML manifest) with embedded base64 images, lacked slide-by-slide navigation, and was built as a vertically scrollable list of 1280x720 slides. We needed to extract all assets, unpack the HTML, and rebuild it into a responsive, slide-by-slide presentation with floating frosted-glass controls, outward-pointing arrows, and the official Keshet logo.

---

## Root Cause
The legacy presentation was generated by an external bundler tool, packing all slides and images into a single file using `<script type="__bundler/template">` and `<script type="__bundler/manifest">`. This made the file unmaintainable, extremely large, and incompatible with our standard slide-by-slide navigation, responsive scaling, and brand watermark system.

---

## What Went Well
1. **Automated Asset Extraction:** Wrote a Node.js script to extract base64-encoded PNGs from the manifest directly to `assets/vibe/`, keeping the repository clean and avoiding large inline base64 blobs in the HTML.
2. **Preserving Aspect Ratio via Proportional Scaling:** Kept the slides at their native 1280x720 dimensions to prevent layout breakage, but used the exact same responsive scaling logic, frosted-glass controls, and keyboard/swipe navigation as the 1920x1080 system.
3. **Watermark Automation:** Programmatically injected the official Keshet logo watermark (`.wm`) onto all 15 slides during assembly, ensuring brand consistency across the entire deck.

---

## What Went Poorly
- Attempting to edit or write the entire 15-slide file directly in a single manual edit was prone to JSON/string formatting errors due to its size. Writing a dedicated Node.js assembly script (`assemble-vibe.js`) completely resolved this and made the build process repeatable and error-free.

---

## How It Was Solved
1. **Unpacked the Bundle:** Used a Node.js script to parse the JSON manifest and extract the raw HTML template.
2. **Extracted Images:** Saved the six embedded base64 PNGs (`dining`, `kitchen`, `waiter`, `haiku`, `sonnet`, `opus`) into `assets/vibe/`.
3. **Assembled the Deck:** Wrote `assemble-vibe.js` to parse the 15 slides, replace image UUIDs with local paths, inject the watermark, and wrap them in the standard responsive `#deck` container with floating navigation.
4. **Cleaned Up:** Deleted all temporary scripts and intermediate files after verification.

---

## Tradeoffs or Alternatives Considered
- **Forcing 1920x1080 dimensions:** We considered resizing the slides to 1920x1080 to match `token-economics-guide.html` exactly. However, because the legacy slides relied heavily on absolute positioning and font sizes optimized for 1280x720, forcing 1920x1080 would have broken the layouts or left massive empty margins. Keeping 1280x720 and scaling proportionally was the superior engineering choice.

---

## Tests Added or Updated
- Verified that `vibe-coding-guide.html` compiled successfully with 15 pages.
- Ran `ReadLints` to ensure the final output is completely free of syntax and markup errors.

---

## Lessons Learned
1. **Build scripts are better than manual edits for large files:** When dealing with multi-slide HTML files, writing a 50-line Node.js script to automate the transformation is faster, cleaner, and less error-prone than manual copy-pasting.
2. **Standardizing "language" doesn't mean forcing identical dimensions:** Responsive scaling allows us to support different aspect ratios (1280x720 and 1920x1080) while providing an identical interactive experience (frosted-glass controls, keyboard shortcuts, branded letterboxing).
